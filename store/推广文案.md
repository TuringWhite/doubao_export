# 推广文案包

> 原则：**讲"备份我自己的聊天记录"，不要讲"爬取豆包数据"**。
> 前者是用户权利，后者会触发平台的敏感词与审核。同一个意思，两种写法，曝光量能差一个数量级。

## 二、V2EX

**节点**：分享创造
**发布时段**：工作日 10:00–11:00 或 20:00–22:00（这两个时段首页刷新快，帖子活得更久）

**标题**

```
[分享创造] 写了个 Chrome 扩展，把豆包的历史对话批量导出成 Markdown
```

**正文**

```
豆包没有批量导出。我账号里 570 条对话，想整理成笔记，手动复制到第 30 条就放弃了。

于是写了个扩展：枚举侧边栏全部对话 → 逐条走接口分页拉全 → 每条对话存成一个 .md。

实测 570 条一次导出成功，0 失败，全程约 5 分钟。

几个实现上的坑，写类似工具的人可能用得上：

1）侧边栏是虚拟滚动列表。
最初的实现是「滚到底 + 等 400ms + 数一下有没有新增」，看起来没问题，
实际只枚举到 5 条——真实数量是 570。两个原因：400ms 等不到懒加载；
真正的 scroller 不是 #flow_chat_sidebar 这个外层容器，而是它的深层子节点，
只滚外层等于没滚。改成每轮滚动所有 overflow-y 可滚动的容器、等 600ms、
连续 3 轮没有新增才收手。

2）角色判定踩了个大坑。
一开始按 user_type === 0 判断用户，结果 409 个导出文件里一条用户消息都没有，
全是 AI。打印字段分布才发现：user_type 实际是 1=用户、2=助手；
而 bot_reply_message_id 在 300/300 条消息上都有（用户消息也带），
完全没有区分度——我第一版就是把它当"助手标记"，于是整篇判成 AI。

3）智能体对话的分页参数不一样。
/chat/bot/chat/:id 首屏要用 anchor=0 + direction=3，
普通对话是 MAX_SAFE_INTEGER + direction=1。不分开处理，智能体那条路径会直接拉空。

其他就是常规活：主世界 hook 抓页面自己的 /im/chain/single 请求（含 aid、
device_id 等会话参数），只覆盖 conversation_id / anchor_index / direction，
所以跟页面真实请求完全一致，不依赖硬编码。

边界我写在前面：
· 只导你自己账号、你自己可见的对话
· 请求只发往 doubao.com，没有后端、没有埋点、不申请 storage 权限
· 导出的只有文字，图片和附件不导
· 需要 Chrome 111+，装的时候要开开发者模式

代码 MIT，随便改：
https://github.com/TuringWhite/doubao_export

（豆包改版比较勤，失效了提 issue，把控制台的 角色字段分布 和 失败明细 贴上来就行，
这种问题一般改几行就能修好。）
```

**2 楼自留（楼主补充，很重要）**

V2EX 的惯例是楼主用 2 楼补充信息，比反复编辑正文好。发布后立刻自己回一条：

```
补充几点，免得重复回答：

· 发布包在 Releases 里，下 zip 解压后「加载已解压的扩展程序」选那个文件夹
· 不支持图片/附件，只导文字（图片是 CDN 链接，导出来意义也不大）
· 目前只支持豆包，DeepSeek/ChatGPT 的接口结构不一样，没做
· 官方有数据导出通道（设置里申请，约 14 天），给的是 JSON 原始数据；
  这个工具是给「想马上拿到可读文件」的场景用的，两者不冲突
· 商店版暂时没上，理由见下面回复
```

## 九、评论区预案（发布前先看一遍）

V2EX / 即刻 的评论基本就这几类。**回复原则：给事实，不辩论，不承诺。**

### Q1「为什么不上架 Chrome 商店？开开发者模式太麻烦」

> 上架要 5 美元开发者费 + 1～3 天审核，而且名字里带"豆包"是商标风险，大概率被拒一次。
> 先用加载解压的方式验证有没有人真的需要，需求够了我再上架。

**别说的**：别说"审核太麻烦懒得弄"——听起来像不打算维护。

### Q2「这算不算违反豆包的用户协议 / 会不会封号」

> 请求走的是网页自己的接口、用你自己的登录态，跟你在页面上点多一次"加载更多"没区别。
> 但批量拉几百条确实会比正常使用密集，我没法保证平台不管，只能说 570 条实测没触发风控。
> 介意的话建议分批导，或者用官方的数据导出申请。

**这是唯一必须诚实回答的问题。** 别拍胸脯说"绝对安全"，出事要担责。

### Q3「会不会偷偷上传我的数据」

> 没有后端。所有请求只发往 doubao.com，grep 一下 content.js 里所有 fetch 就知道了。
> 也没有埋点和 storage 权限，代码全在这儿，自己看比听我说可信。

### Q4「为什么导出来全是 AI / 全是用户」

> 角色字段改版了。F12 里看 `角色字段分布` 那行，把内容贴给我，改几行就好。

这条大概率会出现在你改版之后，先准备好。

### Q5「能导图片 / 附件 / 语音吗」

> 不能，只导文字。图片在接口里是 CDN 链接，会话过期就 404，导出来是死链，意义不大。

### Q6「支持 DeepSeek / ChatGPT / Kimi 吗」

> 接口结构完全不同，豆包这套是 /im/chain/single + 自定义分页锚点，
> 换平台等于重写解析层，暂时没计划。欢迎 PR。

### Q7「Mac / Windows / Edge 能用吗」

> 能。Chromium 内核都行（Chrome / Edge / Brave），跟系统无关。

### Q8「为什么文件名会变成 `标题 (1).md`」

> 同名对话重复导出时浏览器自动加的，不覆盖原文件。这是有意为之，怕你手滑覆盖。

### Q9「导出来 500 多个文件，怎么整理」

> 我是按 obsidian 的用法来的，全丢进一个文件夹，靠 `## 用户` / `## AI` 标题跳转。
> 想合并成一个大文件的话，`cat *.md > all.md` 就行。

### Q10「能不能加个功能：只导最近 N 天 / 按关键词筛选」

> 记下了。现在是一次性全导，加筛选要改枚举逻辑，看有多少人需要。

**别答"马上加"**——你不会有时间，最后变成不守承诺。

### 通用姿势

- 有人说「这不就是爬虫」：不争论，回一句"只导自己账号的对话，跟导出自己的邮件是一个意思"就够
- 有人贴报错：先让他给 `角色字段分布`，别猜
- 有人提 PR：先看有没有补测试，没有就请他补
- 有人纯粹嘲讽：不回。V2EX 上一个不回的楼主比吵赢的楼主体面
